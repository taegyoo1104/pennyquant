# 현재 전략과 검증 방법

이 프로젝트는 **사용자가 정한 전략과 AI 활용을 코드로 구현하고, 실제 자료를 받아 모의매매로 확인하는 개인 프로젝트**입니다. 수익률이 검증된 상품이나 증권사 수준의 거래 시스템을 뜻하지 않습니다.

처음 읽는다면 [매매 과정](TRADING_PROCESS.md)에서 종목 선정부터 매도까지 보고, 용어가 낯설 때 [용어 사전](GLOSSARY.md)을 참고하세요. 이 문서는 현재 설정의 선택 이유와 검사 방법을 설명합니다.

## 지금 사용하는 설정

현재 안내의 권장 실행은 [실시간 단순 눌림목 설정](../config/sessionquant.strategy-lab-websocket.example.yaml)입니다. CLI와 기본 GCP Compose의 기존 기본값까지 자동으로 이 설정으로 바뀐 것은 아닙니다. 아래처럼 설정 파일을 명시하거나 전환 절차를 거쳐야 합니다.

| 항목 | 현재 설정 |
|---|---|
| 시세 | 토스 WebSocket, 필요한 분봉·순위 등은 별도 API 조회 |
| 거래 | 실제 주문을 보내지 않는 모의매매 |
| 가상 초기 자금 | 100달러 |
| 후보·집중 종목 | 토스 제공 미국 상장 주식 중 시총 확인 후보 최대 50개를 하루 고정 → 거래대금 중심 집중 최대 10개 |
| 집중 재선정 | 장전 준비 목록, 이후 정규장 개장 기준 30분 간격 |
| 전략 | 단순 눌림목: 15분봉 상승 → 5분봉 조정 1~4개 → 직전 고가 위에서 반등 마감 |
| 매수 시간 | 개장 75분 뒤부터. 일반 정규장 미국 동부시간 10:45 이상·13:30 미만 |
| RVOL·시장 ETF | 매수 필수 조건 아님. SPY·QQQ·SOXX 카드는 흐름 참고용으로만 조회 |
| 뉴스 AI | 검증된 기업 뉴스를 후보 가점으로 사용 |
| AI 해설 | 기록된 판단과 결과를 한국어로 설명. 주문 입력으로 사용하지 않음 |
| 실제 계좌 조회 | 이 설정에서는 끔 |

**매수 신호와 주문 허가는 별개입니다.** 5분봉 15개·ATR14, 당일 분봉 연속성, 최신 호가, 거래 시간·유동성·자금·손실 한도를 계속 검사합니다. VWAP 부근 지지를 가격 조건으로 요구하지 않아도 공통 지표 계산에 필요한 자료는 있어야 합니다.

## 왜 기존 전략을 단순하게 바꿨나요?

기존 `pullback`은 15분봉 3개 상승, VWAP·EMA 지지, 두 조정봉, 거래량 증가, 과거 20일 RVOL, 시장 방향 등 여러 조건을 함께 요구했습니다. 실제로 받은 자료에 누락·지연·비교 근거 부족이 있으면 조건을 검사하기도 어려웠고, 거래가 없는 이유를 이해하기도 복잡했습니다.

현재 `pullback_simple`은 **상승·조정·반등이라는 기획을 눈으로 확인하기 쉬운 세 규칙**으로 좁혔습니다. 과거 20일 거래량 비교와 시장 ETF 강세를 필수에서 뺐습니다. 누락된 데이터를 정상으로 바꾸거나, 수익을 보장하기 위해 조건을 조정한 것은 아닙니다. 당일 가격 자료의 신선도와 모의 자금 관리는 유지합니다.

두 15분봉만으로 보는 추세는 짧은 구간의 단순한 정의입니다. 상승을 확인한 뒤에도 새 봉에서 조건이 사라질 수 있습니다. 대시보드 단계는 이전 통과 이력이 아니라 **현재 확정봉으로 다시 계산한 상태**입니다.

자세한 조건과 가상의 숫자 예시는 [상승·조정·반등 설명](TRADING_PROCESS.md#3-완성된-차트에서-상승--조정--반등을-찾습니다)에 있습니다. 코드 기준은 [단순 패턴](../sessionquant/market/simple_pullback.py), [공통 신호 검사](../sessionquant/market/strategies.py), [시간표](../sessionquant/session_window.py)입니다.

## 뉴스가 없으면 매매가 멈추나요?

현재 단순 전략에서는 **멈추지 않습니다**. 뉴스 분석이 없거나 호출에 실패해도 뉴스 가점을 0으로 두고 가격 규칙과 보유 관리를 계속합니다. 뉴스 악재만으로 매수를 막거나 강제로 매도하지도 않습니다. 기존 전략과 다른 정책이므로 구분해서 봐야 합니다.

기업 뉴스가 유효하게 검증되면 가점은 호재 10점, 중립 5점, 악재 0점입니다. 유효한 악재가 하나라도 있으면 호재와 평균내지 않고 0점입니다. 뉴스 없음·검증 실패는 0점이지만 ‘악재’라고 표시하지 않습니다. 동일 기사 재분석은 최신 결과를 쓰고 기본 유효 범위는 발행 후 24시간입니다.

모든 기업에 매일 새 공시나 공식 보도자료가 나오지는 않습니다. 제목만 있거나 본문·원문 사용 근거가 부족한 기사도 있습니다. **수집 건수, 고유 기사 수, AI 요청 수, 검증을 통과한 분석 수는 서로 다른 숫자**입니다. ‘기사 수신’이 곧 ‘AI 분석 완료’를 뜻하지 않습니다.

## AI 해설은 무엇을 설명하나요?

별도 해설 작업이 코드의 전략 조건·차단 사유, 최근 뉴스 분석 결과, 모의 체결 기록을 읽고 **시장 상황 / 전략 판단 / 매매 결과**를 한국어로 정리합니다. 자료가 없으면 미확인으로 설명해야 합니다. 원시 경제지표를 자동으로 새롭게 분석하는 기능은 아닙니다.

이 작업은 엔진과 별도로 실행하며, 응답을 기다린다고 시세 처리·청산을 멈추지 않습니다. 현재 전략 실험 설정은 정규장 중 의미 있는 입력이 바뀌었을 때 최소 5분 간격으로 요청하며, 하루 최대 80회 시도합니다. 장 전에는 이 별도 해설을 호출하지 않아 해설 횟수를 아낍니다. 뉴스 수집·개별 분석은 계속하며 전체 호출 한도를 공유합니다. 일자 한도는 UTC 기준이므로 한국 자정과 일치하지 않습니다. 같은 조건이면 기존 설명을 재사용할 수 있습니다.

뉴스와 해설은 AI 비용 한도를 공유합니다. 기본 모델은 `gpt-4.1-mini`, 현재 전략 실험 프로필의 전체 호출 제한은 시간당 120회·하루 600회, 월 비용 한도는 3달러입니다. 이 프로필은 소프트 한도도 3달러로 맞춰 2달러에서 조기에 멈추지 않습니다. 사용 중인 예약 금액까지 합산하므로 실제 확정 비용이 3달러보다 조금 작을 때도 새 호출이 막힐 수 있습니다. 이는 프로그램이 추정·관리하는 한도이며 OpenAI 계정의 충전 잔액과 다릅니다.

새 분석이 제한되거나 실패해도 마지막 성공 설명을 저장해 재접속 후에도 보여 줍니다. 이전 설명의 기준 시각과 새 분석 대기 사유를 구분하며, 과거 설명을 최신 분석으로 표시하지 않습니다. 이전 성공 기록이 없으면 대기 사유만 보입니다. 시장 뉴스·전략 상태·최근 모의매매를 구분하고 긴 설명을 중간에 자르지 않습니다.

입력 기준 시각·생성 시각·모델·호출 ID와 근거를 기록합니다. 형식과 근거 ID를 검사하더라도 자연어 해설의 모든 사실이 검증됐다는 뜻은 아닙니다. **판정·주문·체결 기록이 원본이고 AI 글은 보조 해설**입니다.

전략·백테스트 화면의 금액·비율은 소수점 둘째 자리까지 버려 표시합니다. 낙폭 차트는 비율 대신 % 단위로 보여 주며, 선의 좌표·계산·저장 값은 원래 정밀도를 유지합니다.

## 실제 API 없이 먼저 확인하기

```bash
python -m sessionquant strategy-lab --out data/strategy-lab-check-01
```

기존 결과를 덮어쓰지 않도록 출력 폴더 이름은 새로 정하세요. 생성된 `report.html`을 브라우저에서 열면 조건·뉴스 가점·주문 결과를 볼 수 있습니다. `acceptance.json`과 시나리오별 SQLite 장부에는 상세 결과가 남습니다.

다음처럼 **되어야 할 거래와 되면 안 되는 거래**를 함께 검사합니다.

- 조건 충족 → 모의 매수 → 시간 청산.
- 주문 후 재시작 → 원장 복구 → 중복 매수 없이 청산.
- 오래된 호가 또는 반등 없음 → 신규 주문 없음.
- 뉴스 분석 없음 또는 오류 → 가점 없이 가격 조건과 기존 보유 관리 계속.

이 명령은 **합성 시세와 가상의 LLM 결과**를 사용합니다. 외부 API 키가 필요 없고 실제 AI 요청도 없습니다. ‘실제 뉴스·AI 연결까지 정상’이라는 증거로 쓰면 안 됩니다.

## 실제 시세로 실행하기

[시작 안내](GETTING_STARTED.md)의 MySQL·토스·OpenAI 설정을 준비한 환경에서 실행합니다.

```bash
python -m sessionquant run --config config/sessionquant.strategy-lab-websocket.example.yaml
```

대시보드에서 자료를 확인하고 **매매 시작**을 눌러야 신규 주문 판단이 허용됩니다. 2초 설정은 처리 루프 간격이며 모든 자료가 2초 이내에 들어온다는 보장이 아닙니다. WebSocket은 시세 수신 경로이고 분봉·순위·뉴스는 별도의 처리 시간이 필요합니다.

현재 프로필은 `sessionquant-strategy-lab-ws-v1`이라는 별도 모의 장부 구분을 사용합니다. 예전 장부의 초기 자금·주문·보유가 자동으로 옮겨지지 않습니다. `SQ_DB_NAMESPACE` 환경변수를 직접 고정했다면 장부 구분도 확인해야 합니다. 같은 실행 공간에 엔진을 중복 실행하지 않습니다.

GCP에서는 코드 업데이트와 실행 프로필 전환이 다릅니다. 기본 Compose 파일은 기존 프로필일 수 있으므로 [GCP 안내](GCP_PAPER.md)와 [WebSocket 전환 안내](WEBSOCKET_ROLLOUT.md)를 따릅니다. 기존 보유·미체결 상태와 백업을 확인한 후 전환합니다.

## 무엇까지 확인해야 완료인가요?

규칙별 자동 검사와 합성 시나리오를 통과한 뒤에도 실제 운영은 별도로 확인합니다.

1. 시세·당일 분봉이 도착하고 집중 재선정이 예정대로 진행되는지.
2. 전략 단계와 차단 사유가 실제 입력 시각에 맞게 바뀌는지.
3. 뉴스·AI 요청·응답 검증·비용 기록이 연결되는지.
4. 조건 충족 시 주문과 체결이 기록되고, 손절·청산·재시작 복구가 의도대로 동작하는지.

거래가 없는 날에도 조건이 안 맞은 것인지, 자료나 주문 단계에서 막힌 것인지 설명할 수 있어야 합니다. 테스트 통과나 모의 수익만으로 실거래 가능성·미래 수익을 확정하지 않습니다.
