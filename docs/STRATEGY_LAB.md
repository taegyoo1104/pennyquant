# 기획한 전략과 LLM 활용을 구현하고 검증하기

이 프로젝트의 성공 기준은 수익률이 아니라 **사용자가 정한 매매 규칙, LLM 활용, 규칙대로 이어지는 모의매매**다. 증권사 시스템 수준의 기능을 모두 구현하는 것이 목적은 아니다. 기존 실행과 비교할 수 있도록 새 프로필과 별도 장부를 사용한다.

## 단순 눌림목 v1의 정확한 규칙

`pullback_simple`은 다음 세 조건을 모두 만족하면 신호를 만든다. 미확정봉이나 순간적인 가격 돌파를 사용하지 않는다.

1. **상승 추세:** 최근 확정 15분봉 종가가 직전 확정 15분봉 종가보다 높다.
2. **조정:** 반등봉 바로 앞에 종가가 낮아지거나 같은 5분봉이 연속 1~4개 있다. 그중 한 번 이상은 실제로 낮아져야 한다. 조정 직전 봉의 고가에서 조정 최저가까지 하락 폭은 0보다 크고 5분봉 ATR14의 2.5배 이하다. 5개 이상 계속 내려오면 이 패턴에서는 제외한다.
3. **반등:** 마지막 확정 5분봉 종가가 직전 봉의 고가보다 높다.

VWAP 부근 지지, 15분봉 3개 연속 상승, 반등 거래량 증가, 과거 20일 비교 RVOL, 시장 ETF의 강세 판정은 이 프로필의 매수 필수 조건이 아니다. 거래량 정보가 없다는 이유로 거래량이 많다고 간주하지도 않는다. 같은 조정 시작점을 사용한 신호는 한 번만 주문에 사용하고, 이 전략은 추가매수를 하지 않는다.

매수 시간은 이번 변경에서 유지했다. 당일 5분봉 15개가 필요하며 개장 75분 이후부터 기존 매수 마감까지 판단한다. 신선한 호가, 당일 확정봉의 연속성과 시각, 스프레드·유동성, Paper 상장 참고 자료, 잔액·보유 한도·손실 한도는 계속 확인한다. 가격 손절·시간 청산도 기존 모의매매 엔진을 사용한다. 따라서 세 전략 조건이 맞아도 주문이 보류될 수 있으며 차단 이유를 표시한다.

## LLM의 역할

실제 시세 모드에서는 기존 RSS·공시 등 뉴스 수집 → 실제 LLM 사실 추출 → 원문 근거 검증 → 후보 점수 경로를 사용한다. 뉴스 분석은 후보 우선순위에 최대 10점으로 반영한다. 이 프로필에서는 LLM 결과가 가격 전략을 대신해 주문을 만들거나 뉴스만으로 매매를 차단·강제 청산하지 않는다. API 실패·예산 제한·검증 실패는 **미확인, 가점 0**으로 표시하며 가격 전략과 포지션 관리는 계속한다.

화면에서 마지막 평가의 세 전략 조건, LLM 분석 상태·가점·호출 근거, 주문 판단과 차단 이유를 함께 확인한다. `뉴스·LLM` 화면에는 실제 기사·분석·호출 기록이 있다. `매매 내역`에서 주문 의도와 실제 모의 체결을 구분한다. 거래가 없는 날에도 분석이 없었던 것인지, 조건이 불충족인지, 주문 단계에서 보류된 것인지 확인할 수 있다.

동일 종목의 유효한 기업 뉴스를 합칠 때 기사 수로 투표하거나 긍정·부정을 평균내지 않는다. 검증된 악재가 하나라도 있으면 뉴스 가점은 0점이다. 악재 없이 검증된 호재가 있으면 10점, 검증된 중립만 있으면 5점이다. 검증 실패·뉴스 없음도 가점은 0점이지만 상태는 미확인으로 구분한다. 동일 기사 재분석은 최신 결과만 사용하며, 기본 유효 범위는 발행 후 24시간이다. 이 프로필에서는 악재 가점 0점만으로 매수를 금지하지 않는다.

기업 뉴스는 모든 종목에 매일 발생하는 입력이 아니다. 기본 예제 설정에는 기업별 IR RSS 주소가 등록되어 있지 않으며, SEC 기업 매핑 자동 조회가 RSS 주소까지 찾아 주지는 않는다. 보조 Alpaca 기사는 현재 기업 뉴스 가점에 필요한 1차 출처 검증을 충족하지 않는다. 따라서 기본 설정에서 가점 후보는 주로 최근 공시에 의존하며, 뉴스 가점이 대부분 0일 수 있다. 뉴스 가점만으로 매일 LLM이 거래 후보 순위를 바꾼다고 보장하지 않는다. 전체 수신·재검사 횟수와 종목별 고유 기사 수, 실제 분석 성공 건수는 구분해야 한다.

## 먼저 API 없는 재현 시나리오 실행

```bash
python -m sessionquant strategy-lab --out data/strategy-lab-check-01
```

출력 폴더는 매번 새 이름을 사용한다. `report.html`을 브라우저로 열면 조건·뉴스 가점·주문 결과를 볼 수 있고, `acceptance.json`과 시나리오별 SQLite DB에는 상세 기록이 남는다. 검증 실패 시 명령은 종료 코드 1을 반환한다.

- 조건 충족 → 모의 매수 → 시간 청산.
- 주문 후 엔진 재시작 → 저장 상태 복구 → 중복 매수 없이 청산.
- 오래된 호가 → 주문 없음.
- 반등 없음 → 주문 없음.
- LLM 결과 없음 → 가점 없이 가격 조건에 따른 모의매매.
- LLM 오류 → 오류 기록을 남기고 가격 조건·기존 포지션 관리 계속.

이 명령은 **합성 시세와 가상의 LLM 결과**를 사용한다. 실제 LLM 요청은 0회이고 외부 API 키가 필요 없다. 이는 분석 결과가 들어왔을 때 프로그램이 의도대로 처리하는지 확인하는 재현 경로이며, 실제 AI가 분석했다고 소개해서는 안 된다. 실제 LLM 활용 시연은 아래 실제 시세 모드의 뉴스·호출 기록으로 확인한다.

## 실제 시세 모드 실행

```bash
python -m sessionquant run --config config/sessionquant.strategy-lab.example.yaml
```

토스·MySQL·OpenAI 연결은 기존 설정을 사용한다. 새 설정은 시총 후보 최대 20개, 집중 최대 5개이며 실계좌 모니터링을 끈다. 과거 20거래일 완전성 때문에 운영 후보에서 제외하지 않고 당일 자료를 수집한다. 화면에서 매매 시작을 눌러야 신규 주문 판단을 시작한다.

기존 `sessionquant-realtime-paper-v1`과 다른 `sessionquant-strategy-lab-v1` 장부를 사용한다. 이전 주문·보유·분석 기록은 덮어쓰지 않으며 새 Paper 장부는 설정된 가상 자금으로 시작한다. 환경변수로 `SQ_DB_NAMESPACE`를 고정한 경우에도 새 실행 공간을 지정해야 한다. 같은 토스 인증을 사용하는 기존 엔진은 중지한 뒤 실행한다.

GCP의 기존 `compose.yaml`은 이전 설정을 계속 사용한다. 코드 업데이트만으로 서버의 전략·장부를 자동 전환하지 않는다. 기존 보유·미체결과 백업을 확인한 뒤 실행 설정을 전환하는 배포 작업이 필요하다. 시나리오 검증은 서버 전환 전에 로컬에서 실행할 수 있다.

## 완료 기준

규칙별 단위 검사와 동일 Paper 엔진의 전체 시나리오를 모두 통과해야 한다. 실제 LLM 연결 여부와 가상 결과 주입은 분명히 구분한다. 시세 공급 지연·누락이나 외부 API 장애까지 없다고 보장하지 않으며, 그런 경우에도 실패를 표시하고 중복 주문·기존 기록 손상을 방지하는지를 검증한다.
