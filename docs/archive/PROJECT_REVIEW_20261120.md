## 추가로 구현한 개선

### 1. 실제 실행 시간과 주문 직전 확인

실행기는 한 처리 묶음의 시작 시각을 매매 엔진에 전달합니다. 엔진은 그 시각으로 호가 나이와 매매 시간을 검사합니다. 같은 묶음 안에서 DB 저장·계산이 오래 걸리면 실제 벽시계는 더 진행됐지만 판단 시각은 그대로일 수 있습니다.

토스 자료로 실행할 때는 매수 주문 제출·모의 체결 직전에 실제 실행 시각으로 호가 신선도와 진입 가능 시간을 다시 검사하도록 보강했습니다. 처리 도중 호가가 오래되거나 매수 시간이 끝나면 매수를 보류합니다. 기존 주문 유효기간 또는 취소 확정 시각이 지난 매수 체결도 막습니다. 시계가 뒤로 가거나 읽히지 않아도 허용하지 않습니다. 전략 판단 시각과 기존 신선도 허용 시간은 유지합니다.

추가 검사 결과는 주문·단계별로 기록합니다. 새 기록을 재생할 때는 기록된 검사 결과를 사용하며, 필요한 결과가 없거나 다른 주문의 결과이면 매수를 막고 그 이유를 집계합니다. 과거 검사 기능이 없던 기록과 파일 입력은 기존 논리 시각을 유지합니다. 이 보강은 매수 경로에 적용하며 매도·평가 시각을 실제 시각으로 일괄 변경하지 않습니다.

주문 직전 검사가 웹소켓 연결의 실제 생존 여부까지 즉시 확인하는 것은 아닙니다. 현재 수신과 매매 처리는 같은 이벤트 루프에서 실행되므로 동기 DB 작업 중 발생한 연결 끊김은 그 작업이 끝난 뒤 처리될 수 있습니다. 이번 검사는 그동안 원본 호가가 허용 나이를 넘으면 매수를 막는 보강입니다. 수신 처리와 무거운 작업의 실행 분리는 별도 측정·설계가 필요합니다.

### 2. 화면은 복구 장부 전체 대신 필요한 요약만 읽기

메인 화면은 약 5초마다 엔진 복구 상태를 읽었습니다. 이 상태에는 누적 주문·체결·알림도 포함돼 있어 운영 기간에 따라 읽는 양이 늘어날 수 있었습니다. 메인 화면과 매매 버튼을 그릴 때는 계좌·보유 종목 등 필요한 필드만 DB에서 추출하고, 최근 매도 사유가 필요하면 해당 주문 한 건의 사유만 읽도록 바꿨습니다. 실제 버튼을 누를 때는 원래의 장부 확인을 유지합니다.

AI 비용 계산도 비용·요청 시각 등 네 필드만 읽고, 잔액 확인보다 확실히 이전인 기록은 전송하지 않도록 바꿨습니다. 시각이 잘못됐거나 확인 시각을 걸친 요청은 기존처럼 불확실성을 표시합니다. DB 서버에서 JSON·시각 검사는 여전히 수행하므로 전체 조회 비용이 사라진 것은 아닙니다. 상세 이력 화면의 전체 장부 조회 경로도 남아 있습니다.

격리된 합성 자료에서는 2 MB가 넘는 복구 장부에서 5 KB 미만의 화면 자료만 전달하는 것을 확인했습니다. 이는 전송량 감소 검증이며 실제 GCP의 화면 속도 측정값은 아닙니다.

### 3. 자료 정리의 처리량과 잔여량 측정

현재 종료 시 자료 정리는 시간과 행 수에 상한이 있습니다. 안전하게 짧게 끝나는 장점이 있지만, 10종목을 2초마다 모두 기록하면 6.5시간 동안 호가만 최대 약 117,000행이 생길 수 있습니다. 실제 수신량은 이보다 적을 수 있으며, 현재 한 번의 정리는 전체 대상에서 최대 50,000행을 검사합니다.

정리 후 남은 검사 예산 안에서 잔여 자료, 가장 오래된 정리 대상, 이전 측정 이후 추가된 자료 수를 확인하도록 보강했습니다. 전체를 확인하지 못하면 “최소” 또는 “미확인”으로 표시합니다. 정리 작업 완료와 잔여 자료 없음은 구분하며, 한도에 반복해서 도달하면 시스템·설정 화면에 점검 안내를 표시합니다. 삭제 대상·보존 기간·백업 확인·실행 잠금·50,000행/90초 상한은 유지했습니다.

폐기 가능한 MySQL에 만료된 호가 120,000행을 넣은 실험에서는 50,000 → 50,000 → 20,000행씩 정리됐습니다. 앞선 두 번은 잔여량을 추가로 검사할 예산이 없어 “미확인”, 두 번째에는 반복 한도 도달 안내가 나왔고 마지막에 잔여 없음이 확인됐습니다. 실제 유입량은 운영 자료로 확인한 뒤 정리 빈도나 한도를 조정해야 합니다. 백업 크기만으로 삭제 효과를 판단하지 않습니다.

### 4. MySQL 변경에 대한 자동 검사 범위

push·PR에서 오프라인 회귀 검사를 통과하면 폐기 가능한 MySQL 통합 검사가 자동 실행되도록 바꿨습니다. 수동 실행에서만 MySQL 검사를 생략할 수 있습니다. 운영 DB나 운영 자격 증명은 사용하지 않습니다.

### 5. 기존 엄격한 모의 프로필의 미체결 주문 재검사

현재 권장 모의 정책은 체결 때 상장 자료와 웹소켓 사용 가능 여부를 다시 확인합니다. 별도의 기존 엄격한 정책에서는 매수 주문 뒤 종목 적격성이 제한 상태로 바뀌어도 이미 대기 중인 주문의 체결 경로에 그 제한이 모두 전달되지 않는 경우를 재현했습니다.

새 실제 실행 검사에서는 두 정책 모두 주문 제출·매수 체결 직전에 해당 정책의 종목 적격성을 다시 확인합니다. 처리 중 자격 자료가 만료되거나 제한 상태로 바뀌면 매수를 보류하고 검사 결과를 기록합니다. 기존 기록을 재생할 때는 당시 검사 계약을 유지하므로, 과거 기록에 새 검사를 소급 적용한 결과로 바꾸지 않습니다.
