# 08A 통합 대시보드와 안전한 매매 제어

## 후속 개선: 쉬운 화면과 뉴스 진행 상황

메인은 실행 상태, 모의 자산·주문 가능 금액·손익·AI 비용 네 카드, 보유 종목, 최근 거래, 뉴스 처리 요약으로 구성한다. 긴 정책 설명은 시스템 상세나 도움말로 옮겼다. 공통 표의 열 이름·처리 상태·제외 사유는 쉬운 한글로 표시하며 저장된 코드와 기사/분석 원문은 보존한다. 아직 이름이 없는 항목은 원본 기록 보기에서 확인할 수 있다.

기사 수신·AI 요청·응답 검사 통과는 각각 집계한다. 메인은 최근 최대 300건, 뉴스 상세는 수신 2,000건/호출 500건 중 최근 24시간 범위다. 중복 수신·이전 분석 재사용·실패·미확인 결과를 구분하며 응답 검사 성공을 분류 정답이나 매수 승인으로 표시하지 않는다. 메인과 뉴스 화면 모두 선택한 자동 새로고침을 적용한다. 새로고침은 외부 호출이나 주문을 시작하지 않는다.

아래는 최초 08A 구현 기록이며 현재 화면의 문구·추가 뉴스 집계는 이 절을 따른다. 읽기 전용 진단 명령은 [실행 안내](../../REALTIME_PAPER.md)를 참고한다.

기준: 사용자 첨부 `08A_통합_대시보드_UI_UX_매매제어.txt`, 시작 HEAD `bd7ce6e`. 로컬 PC/MySQL·Paper 우선, 이후 GCP 이전, KIS 제외를 유지한다. 09/10 실거래 통합이나 실제 계좌 활성화는 포함하지 않는다.

## 화면 구성과 변경 파일

상단에 정확히 여섯 화면을 둔다. Streamlit radio를 공통 내비게이션으로 사용하고 선택한 화면만 렌더링한다. 모든 `st.tabs` 내용을 동시에 실행하던 방식 대신 화면별 지연 조회·렌더링을 사용한다.

| 대시보드 | 매매 제어, 네 카드, 관리 보유 최대 5개, 최근 체결 5개, 관련 기업 뉴스 5개 |
| 시장·종목 | SPY/QQQ, 참고 ETF와 FRED, 시총 감시/집중 목록, 데이터 품질·후보 순위·기술 근거 |

`session_app.py`는 기존 세부 렌더러를 재사용하며 메인에서 전체 계좌 상세·예약금·시장/기술 표·긴 오류·전체 뉴스·LLM 토큰 표를 제거했다. `overview.py`는 메인 뷰·뉴스·체결·비용 집계·상세 이동을 담당한다. `reference_panel.py`는 유효하지 않은 가격/변화율을 감추고 전일/5분/15분/30분·공급원·수집/원본 시각을 구분한다. `account_app.py`는 조회 화면에서 제어를 읽기 전용으로 제한한다. `trading_controls.py`는 기존 명령 큐만 사용한다. 스키마·기존 주문/기사 ID·전략·위험 한도는 변경하지 않는다.

다크 배경, 텍스트를 병기한 상태와 BUY/SELL 구분, 데스크톱 네 카드·중간 폭 두 열·모바일 한 열을 제공한다. 자동 갱신은 메인만 5초이며 상세 화면은 선택/수동 갱신 시 읽는다. `전체 보기`는 해당 상세 화면으로 이동한다. 실행별 확인 체크와 거래/LLM 검색 상태는 화면 이동에도 보존한다.

## H / F와 뉴스

- H: 활성 Paper 전략 장부의 양수 관리 포지션. LIVE 화면의 관련 뉴스 H는 실제 계좌 스냅샷의 양수 보유이며 Paper와 합산하지 않는다. LIVE 관리 포지션 매도 권한과는 별개다.
- F: `watchlist_dashboard_v1`의 상태 VALID, 최근 갱신 유효, `focused=true`, 개별 `focus_valid_until`이 유효한 현재 종목만 사용한다. 과거 집중 목록을 되살리지 않는다.
- 기사: 원본 `news_events`의 명시적 symbols와 기존 기업 뉴스 검증 계약을 사용한다. 분석은 내장 원본 event 또는 정확한 article/event ID로만 연결한다. 제목·LLM 추측으로 연결하지 않는다.
- `main_news`는 데이터와 평가 시각을 명시한 순수 함수다. 검증된 발표 시각의 최근 24시간, 수신/분석 미래 제외, 오류 제외, H∪F 관련 기업만 선택하고 기사 ID로 중복을 합친다. 다른 연결 종목의 라벨을 메인에 섞지 않는다.
- 집중 목록 미확인과 수집 상태 미확인은 별도 경고다. 전체·오래된·오류·미확인 기사와 거시 뉴스는 상세 화면에서 유지한다. 메인 필터가 수집/LLM/위험 정책을 변경하지 않는다.

## 금액과 최신성

메인 카드 네 개는 활성 장부의 USD 총자산 또는 실제 미국 주식 평가금액, USD 매수 가능 금액/가용 현금, 오늘 순실현손익, LLM 월 추정 사용액/자체 예산 잔여다. 실제 계좌의 매수 가능 금액을 현금·총자산으로 바꾸지 않고 원화·Paper와 합산하지 않는다. Paper 가용 현금은 cash−reserved_cash다.

순실현손익의 기존 엔진 산식은 매도금액−배분 매수원가−배분 매수비용−매도비용이다. 체결별 `realized_pnl`을 재계산하거나 추정 수수료를 공식 실비로 바꾸지 않는다. BUY의 실현손익과 미확인 수수료는 `—`다. **현재 자료 계약에는 하루 전체 집계의 완전성 증거가 없어 오늘 순실현손익 카드는 N/A다.** 최근 300건이나 누적 손익을 오늘 손익으로 대체하지 않는다. 누적·체결별 장부 수치는 상세에서 확인한다.

현재 매수호가의 원본 시각이 60초를 초과하거나 미확인이면 평가금액/평가손익은 `—`다. 매수가를 현재가로 대입하지 않는다. 평균 매수가 누락도 `—`다. 실제 계좌 실패·과거 스냅샷은 마지막 확인 값임을 표시한다.

LLM 카드는 월별 `session_llm_budget_v1`과 한도 제어에서만 읽는다. 잔여=월 한도−프로그램 추정 사용−예약이며 0 아래로 표시하지 않는다. OpenAI 실시간 선불 잔액으로 표시하지 않는다. 수동 확인 기반 추정 잔액·공식 조직 비용·토큰/호출은 뉴스·LLM에서 별도 표시한다.

ETF는 GOOD이고 유효한 근거만 가격/변화율로 표시하며 DELAYED를 REALTIME으로 승격하지 않는다. STALE 숫자는 숨긴다. 전일 비교는 cross-day comparability 확인 시에만 표시한다. SHY/IEF/TLT는 국채 ETF 가격, USO는 원유 선물 노출 ETF이며 금리/현물 유가로 환산하지 않는다. FRED는 관측 날짜와 수신 시각이 별도인 공식 일별 자료다. 이 UI가 시장 필터를 활성화하지 않는다.

## 요청·권한·멱등성

`start`, `stop_all`, `sell_symbol`은 `order_intents(kind=dashboard_command)`로만 기록하고 기존 엔진 ACK·체결 대사를 사용한다. 브로커 매수/매도 API를 UI에 추가하지 않았다.

`request_command`는 SQLite/MySQL의 기존 `update_control` 행 잠금 안에서 실행 ID·환경/모드·armed·heartbeat TTL을 재검증한다. 시작은 WAITING에서만 가능하며 pending 동일 action/symbol은 기존 요청을 반환한다. 실행/heartbeat/action/symbol 기반 ID로 같은 화면 상태의 재전송도 멱등 처리한다. 기존 엔진의 종료 우선순위·TTL·계좌 일치·권한 검사는 유지한다.

시작·종료·종목 매도는 최종 확인 후 버튼에서만 발생한다. 확인은 run ID별로 분리되어 재시작한 엔진에 이전 확인을 사용하지 않는다. 종료 확인은 관리 티커/수량·시장가 위험을 표시하고 LIVE에는 마스킹된 추가 확인을 요구한다. UI는 계좌 전체 식별자를 표시하지 않는다.

Paper 전량 매도는 현재 저장 장부의 양수 관리 수량과 진행 중인 매도 주문을 서버 측에서 재확인한다. **LIVE 관리 포지션 출처는 아직 공통 인터페이스로 연결되지 않아 개별 LIVE 매도는 비활성화한다.** 실제 계좌 조회 전용 화면도 readonly다. 외부 보유를 자동 청산 대상으로 삼지 않는다. ACK accepted를 전량 체결로 표시하지 않고 부분/미확인·잔량은 상세로 보낸다.

## 성능·검증과 한계

DB 상태·H/F·뉴스는 하나의 트랜잭션 스냅샷으로 읽는다. 메인은 체결/원본/분석/호가 각 최대 300건과 제어 집계를 읽고 긴 상세 기록은 조회하지 않는다. 화면에 조회 범위를 명시한다. 상세는 기존 최대 2,000건 범위이며 전체 장기 기록은 `record-export`를 사용한다. 대량 뉴스에서 메인 관련 기사 누락 가능성이 있으므로 전체 이력에서 관련 기사를 모두 조회하는 보장은 아니다.

격리된 소규모 SQLite fixture에서 메인 `load_database + build_view` 20회 중앙값 0.95ms/최대42.0ms였다. 네트워크·브라우저·대형 MySQL 시간을 포함하지 않으며 운영 5초 SLA를 보증하지 않는다. 비용 카드는 매 갱신 때 전체 LLM 호출 원장을 훑지 않는다.

새 08A 단위/UI 회귀 22건과 MySQL 연결 간 멱등성 1건을 추가했다. 기존 01/02/06/07/08 UI 검사는 새 목적지로 이동한 후 원래 만료/UNKNOWN/사용량/순위 검증을 유지한다. 자동 갱신·탭 이동만으로 명령이 생기지 않는지 검사한다.

헤드리스 Chromium에서 빈 화면과 명시적 합성 fixture, 1,440px/390px, 여섯 화면 이동을 확인했다. 모바일 document width=390px, viewport=390px, 오류 0·메인 카드 4개·내비게이션 6개다. 공유 데스크톱 도구가 제공되지 않아 반복 가능한 로컬 브라우저 검증을 사용했다. 사용자 계좌/키는 사용하지 않았다. 최종 테스트 횟수는 [HANDOFF](../../../HANDOFF.md) 최신 절을 따른다.

운영 장기/대용량 성능·실제 토스 자료·Windows ACL/모바일 기기의 실사용은 미검증이다. MFE/MAE·세부 전략 성과는 실제 보고서에 없는 값을 생성하지 않는다. 일별 순실현손익 완전성, 페이지를 넘는 전체 이력/관련 뉴스 SQL 조회, LIVE 관리 포지션 provenance와 전량 매도는 후속 인터페이스 보완 대상이다. **09 개발 준비 자료는 제공했지만 실거래 활성화·10 운영 승인은 보류한다.** 실제 주문·유료 LLM·사용자 DB 접근은 0건이다.
