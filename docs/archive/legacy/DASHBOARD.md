# PennyQuant 대시보드

프로젝트 루트에서 실행합니다.

```bash
streamlit run pennyquant/dashboard/app.py -- --db data/pennyquant.db --report data/report.json
```

`PQ_DB`, `PQ_REPORT` 환경변수로 기본 경로를 바꿀 수 있습니다. 명령행 인수가 환경변수보다 우선합니다. 브라우저는 Streamlit이 안내하는 주소로 접속합니다. 기본 주소는 `http://localhost:8501`입니다.

화면은 저장된 SQLite 기록과 JSON 성과 보고서를 읽습니다. 수집·전략·주문 엔진을 시작하는 기능은 없습니다. 브라우저가 열린 동안 기본값으로 **3초마다 자동 갱신**하며, 사이드바의 **자동 갱신 · 3초**를 끄면 수동 갱신으로 전환합니다. **데이터 새로고침**으로 즉시 다시 읽을 수 있습니다. DB나 보고서가 없더라도 대기 화면으로 열립니다.

## 화면 구성

| 화면 | 확인할 내용 |
|---|---|
| 시장 모니터링 | 관심 종목 가격, 등락률, 상대 거래량, 거래대금, 스프레드, 1분봉, 뉴스 발표·수신 시각 |
| 주문 · 포지션 | 실제 모의체결 수량, 평균 매수가, 손절·익절 목표, 주문 상태, 체결 내역, 신호 근거 |
| 전략 분석 | 네 가지 전략의 비용 차감 성과, 거래 수, 승률, Profit Factor, 낙폭, 자산 곡선, JSON 다운로드 |
| 시스템 관리 | 모의매매 모드, 신규 진입 제한 사유, 마지막 이벤트 시각과 경과 시간, 연결 확인 상태, 로그, 데이터 경로 |

모든 표시 시각은 한국 표준시(KST)입니다. 거래 세션 판정은 엔진이 미국 동부시간과 거래소 달력을 사용합니다. 통화는 USD입니다.

**신규 진입 중지**는 DB의 `manual_halt` 제어값을 `true`로 저장합니다. 연속 모의매매(`paper --follow`) 엔진은 이벤트 대기 중에도 약 0.2초 간격으로 제어값을 확인해 적용합니다. 파일 재생 엔진은 다음 이벤트 처리 시 적용합니다. 보유 포지션의 위험 관리와 주문 상태 확인은 계속합니다. **신규 진입 재개**는 사용자 중지만 해제하며, 일일 손실·미확인 주문·잔고 불일치 등 다른 제한은 해제하지 않습니다. DB를 아직 만들지 않았다면 제어 버튼은 비활성화됩니다.

마지막 이벤트는 DB의 `runtime.last_event`를 사용하며, 화면 갱신 시각과 구분합니다. 현재 시각 대비 이벤트 경과가 5초를 넘으면 최신 이벤트가 없다고 표시합니다. 이는 API 연결 여부의 확정 판정이 아닙니다. 합성·과거 재생 데이터는 과거 이벤트 시각이라는 설명과 함께 표시하며 실시간 연결로 표시하지 않습니다.

합성 데이터 보고서(`synthetic: true`)는 상단에 데모임을 표시합니다. 저장 데이터만으로 실시간 API 연결 상태를 추정하지 않습니다. 실거래 활성화 버튼은 없습니다.

대시보드는 개인용 로컬 사용을 기본으로 합니다. 외부에 노출할 경우 접근 통제와 서버 설정을 별도로 검토하세요.
