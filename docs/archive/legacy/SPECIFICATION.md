# 미국 페니스탁 뉴스 기반 알고리즘 트레이딩 시스템 개발 계획서

**프로젝트명:** PennyQuant  
**버전:** 1.0  
**작성일:** 2026년 11월 13일  
**개발 방식:** Python 기반 개인용 자동매매 시스템  
**대상 시장:** 미국 주식시장(NASDAQ, NYSE 등)  
**거래 증권사:** 토스증권  
**초기 투자금:** 약 100,000원 상당의 미국 달러

---

## 1. 프로젝트 개요

### 1.1 개발 목적

토스증권 Open API를 활용해 미국 저가주식(페니스탁)의 실시간 시세 및 뉴스를 수집하고, 이를 분석하여 자동으로 매수·매도하는 알고리즘 트레이딩 시스템을 개발한다.

시스템은 단순한 기술적 지표 기반 자동매매가 아니라 다음 세 가지 요소를 결합하는 것을 목표로 한다.

1. **뉴스 분석:** 기업의 호재·악재 및 주요 이벤트 감지
2. **시장 분석:** 거래량, 가격 움직임, 유동성, 매수세 분석
3. **자동매매:** 매매 신호 발생 시 위험 관리 조건을 검증한 후 주문 실행

초기 투자금은 약 10만 원으로 제한하며, 수익 극대화보다 전략의 실효성 검증과 안정적인 자동매매 시스템 구축을 우선한다.

### 1.2 핵심 개발 원칙

- 실제 매매 전략은 백테스트와 모의매매 결과를 통해 선정한다.
- 실시간 뉴스만을 근거로 무조건 매수하지 않는다.
- 거래 비용, 슬리피지 및 미체결 가능성을 반영한다.
- 증권사 API 연결 장애에도 중복 주문이 발생하지 않도록 한다.
- 모든 매매 결정과 실제 체결 결과를 데이터베이스에 기록한다.
- 초기 개발에서는 유료 뉴스 및 시세 서비스 사용을 최소화한다.
- 실거래 활성화 전에는 명시적인 수동 승인 과정을 거친다.

## 3. 시스템 아키텍처

전체 시스템은 데이터 수집, 신호 분석, 위험 관리, 주문 처리, 결과 저장의 다섯 계층으로 분리한다.

**전체 데이터 흐름**

```text
[실시간 데이터 수집]
   ├─ 토스증권 시세 API
   ├─ 토스증권 WebSocket
   ├─ Alpaca 뉴스 API
   ├─ SEC EDGAR
   └─ 기업 보도자료 RSS
             ↓
[데이터 처리]
   ├─ 종목 코드 매칭
   ├─ 뉴스 중복 제거
   ├─ 뉴스 이벤트 분류
   ├─ 거래량 및 가격 지표 계산
   └─ 유동성 필터링
             ↓
[트레이딩 전략 엔진]
   ├─ 뉴스 모멘텀 전략
   ├─ 눌림목 전략
   ├─ 갭 돌파 전략
   └─ VWAP 전략
             ↓
[위험 관리 엔진]
   ├─ 주문 금액 제한
   ├─ 스프레드 검사
   ├─ 손절/익절 계산
   ├─ 중복 주문 방지
   └─ 일일 손실 한도 검사
             ↓
[주문 실행 엔진]
   ├─ 모의주문
   └─ 토스증권 실주문
             ↓
[데이터 저장 및 대시보드]
   ├─ 수집 데이터
   ├─ 전략별 신호
   ├─ 주문·체결 내역
   ├─ 실현 및 미실현 손익
   └─ 시스템 오류 로그
```

각 모듈은 독립적으로 실행 및 테스트할 수 있도록 설계한다.

## 4. 데이터 수집 시스템

### 4.1 주식시장 데이터

**데이터 제공:** 토스증권 Open API

수집 항목은 다음과 같다.

- 종목 코드, 현재가, 전일 종가
- 당일 상승률 및 거래량
- 1분봉 OHLCV
- 매수·매도 호가 및 잔량
- 체결 가격과 수량
- 거래 가능 여부 및 시장 운영 상태

전체 미국 주식을 지속적으로 WebSocket 구독하지 않는다.

먼저 거래량·등락률 랭킹과 현재가 조회를 통해 후보 종목을 추출한 다음, 선정한 종목만 실시간으로 구독한다.

초기에는 최대 20개 후보를 관리한다.

토스 WebSocket은 연결 및 구독 수에 제한이 있으므로, 종목별 구독 수를 합산하여 한도를 초과하지 않도록 한다.

### 4.2 뉴스 데이터

**1차 뉴스 제공:** Alpaca News API

- 기업 관련 뉴스 제목
- 관련 티커
- 기사 발행 시간
- 실제 수신 시간
- 제공 언론사
- 뉴스 원문 URL
- 기사 요약 및 본문(제공되는 경우)

계정별 실시간 뉴스 접근 권한을 먼저 검증한다. 실시간 수신이 불가능하거나 지연되는 경우 해당 데이터는 즉시 매매 신호 대신 보조 분석 데이터로 사용한다.

**2차 데이터 제공:** SEC EDGAR

감시 대상 공시는 다음과 같다.

| 공시 | 분석 목적 |
|---|---|
| 8-K | 주요 기업 이벤트 |
| 6-K | 미국 상장 외국기업의 주요 보고 |
| S-3 | 주식 등록 및 잠재적 자금조달 |
| 424B5 | 증권 발행 조건 및 희석 가능성 |
| 10-Q / 10-K | 재무 건전성 및 위험 분석 |

SEC 데이터는 공개 API 사용 규정을 준수하며 수집한다. 공시 양식만으로 호재·악재를 확정하지 않고 내용을 분석한다.

**3차 뉴스 제공:** GlobeNewswire 등의 공개 RSS

신제품 출시, FDA 관련 발표, 대규모 계약, 인수합병 등 기업 보도자료를 보완적으로 수집한다.

### 4.3 뉴스 분류 엔진

뉴스는 다음과 같이 분류한다.

| 뉴스 유형 | 초기 처리 |
|---|---|
| FDA 승인 및 임상 긍정적 결과 | 긍정 후보 |
| 대규모 계약·파트너십 | 긍정 후보 |
| 예상보다 좋은 실적 | 긍정 후보 |
| 인수합병 관련 확정 발표 | 개별 분석 |
| 유상증자·주식 추가 발행 | 희석 위험 확인 |
| 상장폐지 위험 | 매수 제한 후보 |
| 임상 실패 및 규제 조치 | 부정 후보 |
| 단순 주가 상승 기사 | 매수 근거에서 제외 |
| 소문·출처 불분명 | 거래 제외 |

초기 분류는 규칙 기반으로 구현한다.

이후 충분한 데이터가 축적되면 자연어처리 모델을 적용해 이벤트 분류 정확도를 개선한다.

뉴스가 긍정적으로 분류되더라도 즉시 주문하지 않고, 실제 시장 반응을 통해 신호를 검증한다.

## 5. 종목 탐색 및 필터링

### 5.1 기본 종목 조건

| 항목 | 초기 조건 |
|---|---|
| 주가 | $1.00~$5.00 |
| 거래시장 | 미국 정규 거래소 |
| 당일 상승률 | +10% 이상 |
| 상대 거래량 | 동일 시간대 과거 평균 대비 3배 이상 |
| 당일 누적 거래대금 | $200만 이상 |
| 매수·매도 스프레드 | 0.5% 이하 |
| 주요 이벤트 | 최근 24시간 내 관련 뉴스 우선 |
| 거래 가능 상태 | 정상 거래 종목 |

위 조건은 실험을 위한 기본값이며, 전략 최적화 과정에서 조정한다.

과거 동일 시간대 데이터가 충분하지 않으면 상대 거래량을 임의로 계산하지 않고 해당 지표를 미확인 상태로 처리한다.

### 5.2 매수 제외 조건

다음에 해당하는 종목은 초기 단계에서 거래하지 않는다.

- OTC 및 주문 가능 여부가 불명확한 종목
- 현재 거래가 정지된 종목
- 스프레드가 지나치게 넓은 종목
- 거래량이 급감하고 호가 잔량이 부족한 종목
- 이미 당일 고점 대비 급락 중인 종목
- 공시상 중대한 희석 위험이 확인된 종목
- 분할·병합 등 기업행동으로 가격 비교가 불안정한 종목
- 실시간 시세가 오래되었거나 뉴스 발표 시간을 확인할 수 없는 종목

## 6. 매매 전략 설계

초기 시스템에는 네 가지 전략을 독립적으로 구현한다.

### 전략 A. 뉴스 기반 모멘텀

**목적:** 긍정적인 기업 이벤트와 실제 매수세가 함께 나타나는 종목의 상승 추세 포착

진입 절차:

1. 긍정적 뉴스 이벤트 탐지
2. 종목의 거래 가능 상태 검사
3. 거래량 및 거래대금 급증 여부 확인
4. 실제 호가 스프레드 검사
5. 상승 추세가 유지되는지 분석
6. 조건 충족 시 매수 신호 생성

### 전략 B. 급등 후 눌림목 매수

**목적:** 최초 급등을 추격하지 않고 되돌림 이후 상승 재개를 확인

진입 절차:

1. 거래량 급증 종목 확인
2. 첫 상승 구간의 고점 기록
3. 가격의 일시적 되돌림 관찰
4. 최근 지지선 및 VWAP 유지 여부 확인
5. 거래량을 동반한 반등 확인
6. 직전 단기 고점 돌파 시 진입 후보 생성

초기 최우선 검증 전략으로 선정한다.

### 전략 C. 갭 상승 후 돌파

**목적:** 장전 호재로 가격이 상승한 종목이 정규장에서도 추세를 이어가는 경우 포착

진입 절차:

1. 전일 종가 대비 갭 상승 종목 탐색
2. 갭 발생 원인 확인
3. 개장 이후 첫 5분간 가격 범위 기록
4. 고점 돌파 및 재진입 패턴 분석
5. 충분한 거래량 확인 후 신호 생성

### 전략 D. VWAP 회복

**목적:** 단기 조정 이후 매수세가 회복되는 구간을 포착

진입 절차:

1. 강한 상승 이력이 있는 종목 선별
2. 가격이 VWAP 아래로 내려간 구간 확인
3. 거래량을 동반한 VWAP 재돌파 탐지
4. 단기 추세 전환 확인
5. 위험 대비 기대수익 검증 후 진입

### 전략 비교 기준

네 전략은 동일한 기간과 거래 비용 가정에서 비교한다.

주요 평가 지표:

- 거래당 평균 순손익
- 승률
- 손익비
- Profit Factor
- 최대 낙폭(MDD)
- 연속 손실 횟수
- 미체결 및 슬리피지 발생률
- 거래 빈도
- 전략별 자본 효율

전략 파라미터는 학습 데이터에서 조정하고, 별도 검증 기간과 실시간 모의매매로 재평가한다.

## 7. 위험 관리 및 자금 운용

### 7.1 초기 투자금 운영

총자본은 약 10만 원 상당의 달러로 설정한다.

초기 위험 관리 규칙은 다음과 같다.

| 항목 | 설정 |
|---|---|
| 전체 자본 | 약 $70(예시) |
| 1회 위험 예산 | 총자본의 1% |
| 기본 손절 기준 | 진입가 대비 -5% |
| 기본 익절 기준 | 진입가 대비 +10% |
| 일일 최대 손실 예산 | 총자본의 2% |
| 일일 신규 진입 | 최대 2회 |
| 동시 보유 종목 | 최대 1개 |
| 레버리지 | 사용하지 않음 |
| 추가 매수·물타기 | 초기에는 금지 |

실제 매수 수량은 다음 식으로 계산한다.

**주문 금액 = 최소값(가용 현금, 거래당 위험 예산 ÷ 예상 손절 비율)**

단, 예상 손절 비율에 수수료·스프레드·슬리피지를 고려해야 한다. 정수 주식 수량 제한이 있으면 주문 가능한 수량으로 내림한다.

손절 가격은 목표 수준일 뿐이며 급락이나 거래정지 상황에서는 예상보다 큰 손실이 발생할 수 있다.

### 7.2 자동 거래 중단 조건

다음 상황에서는 새로운 매수를 즉시 금지한다.

- 일일 누적 손실 예산 초과
- 연속 손절 2회 발생
- 뉴스 및 시세 데이터가 오래되어 신뢰할 수 없는 경우
- 계좌 잔고와 내부 보유 수량이 일치하지 않는 경우
- 주문 결과를 확인할 수 없는 경우
- API 장애 및 인증 오류 발생
- 사용자가 수동으로 매매 중단을 실행한 경우

중단 이후에도 이미 보유한 포지션의 위험 관리와 상태 확인은 계속 수행한다.

## 8. 자동주문 처리 시스템

### 8.1 주문 절차

1. 전략 엔진에서 매수 신호 수신
2. 거래 가능 시간·종목 상태 확인
3. 최신 호가 및 잔고 조회
4. 주문 수량 산출
5. 위험 관리 엔진 승인
6. 고유 주문 ID를 부여해 지정가 매수
7. 주문 체결 상태 확인
8. 실제 체결 수량에 대한 손절·익절 조건주문 등록
9. 매도 체결 및 거래 종료 확인
10. 최종 손익을 DB에 기록

토스증권의 OCO 조건주문이 해당 주문 유형과 세션에서 원하는 방식으로 작동하는지 검증한 후 사용한다.

### 8.2 주문 안전성

- 각 주문에 고유한 `clientOrderId` 부여
- 주문 타임아웃 발생 시 무조건 재주문하지 않음
- 먼저 기존 주문 상태를 조회한 뒤 재시도
- 부분 체결된 수량에 대해서만 매도 관리
- 매수 미체결 시 일정 시간이 지나면 주문 취소 검토
- 웹소켓 재연결 시 REST API로 주문·잔고 상태 재확인
- 서버 재시작 시 기존 보유 포지션과 대기 주문 복구

## 11. 백테스트 및 모의매매

### 11.1 백테스트

과거 시장 데이터와 뉴스 발생 시점을 이용하여 전략별 성과를 비교한다.

기본 조건:

- 거래 비용을 포함한 성과 산출
- 스프레드와 슬리피지 반영
- 실제 주문 가능한 수량만 거래
- 데이터에 존재하지 않는 미래 뉴스 사용 금지
- 상장폐지 종목 누락에 따른 생존편향 검토
- 기업행동에 따른 가격 조정 검증

과거 뉴스의 발행 시각과 실제 수신 시각은 다를 수 있으므로, 신뢰할 수 있는 실시간 수신 이력이 없는 과거 뉴스 데이터로 초단타 전략의 성과를 과대평가하지 않는다.

### 11.2 모의매매

시스템이 실제 장에서 실시간으로 신호를 생성하도록 하고 주문만 가상으로 처리한다.

최소 4주 이상 검증하되, 거래 사례가 충분하지 않다면 기간을 연장한다.

실제 매수 가능 호가, 매도 가능 호가, 체결 가능 수량, 지연을 반영하여 모의체결을 추정한다.

### 11.3 실거래 전 승인 기준

아래는 개발자가 설정하는 초기 통과 기준이다. 전략의 수익성을 보장하지 않는다.

- 별도 검증 기간에서 순기대수익이 양수
- 모의매매에서도 거래 비용 차감 후 손익이 양수
- 모의매매 기준 Profit Factor 1.2 이상
- 위험 한도 위반 0건
- 중복 주문 및 포지션 불일치 0건
- API 장애·재연결 복구 테스트 통과
- 주문 중단 기능 정상 작동

표본이 충분하지 않은 경우에는 기준을 만족하더라도 실거래를 보류한다.

## 13. 개발 단계 및 일정

| 단계 | 기간 | 개발 내용 | 완료 기준 |
|---|---|---|---|
| 1단계 | 1주 | 토스 API 인증, 시세, 계좌 연결 | 시세·잔고 정상 수신 |
| 2단계 | 1주 | 종목 스캐너, WebSocket, DB | 관심 종목 실시간 추적 |
| 3단계 | 1주 | 뉴스 수집, 분류, 이벤트 연결 | 종목별 뉴스 자동 기록 |
| 4단계 | 1주 | 네 가지 매매 전략 구현 | 매매 신호 자동 생성 |
| 5단계 | 1주 | 백테스트, 모의주문, 위험 관리 | 비용 포함 성과 분석 |
| 6단계 | 1주 | 대시보드, 주문 처리, 장애 복구 | 통합 테스트 통과 |
| 검증 | 4주 이상 | 실시간 모의매매 | 성과 및 안정성 검증 |
| 실거래 | 조건 충족 시 | 제한된 자본으로 실주문 | 위험 관리 규칙 준수 |

개발 일정은 1인 개발을 가정한 목표 일정이며, API 접근 조건 및 테스트 결과에 따라 변경될 수 있다.

- 관심 종목으로 선정한 종목만 상세 수집한다.
- 장 종료 후 불필요한 API 요청을 중단한다.
- 무료 데이터 접근 조건을 먼저 검증한다.
- 뉴스 분석은 초기에는 규칙 기반으로 운영한다.
- 시스템이 안정화된 후에만 상시 클라우드 운영을 검토한다.
