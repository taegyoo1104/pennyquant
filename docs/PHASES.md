# SessionQuant Phase 0~4 구현·검증 단위

각 단계는 별도 커밋 또는 검토 가능한 파일 묶음으로 구분합니다. 이 문서는 새 모의매매 구현 범위와 별도 검증이 필요한 항목을 구분합니다. 최종 테스트 결과는 통합 검증 후 아래 기록에 반영합니다.

| 단계 | 주요 파일·영역 | 검증할 동작 |
|---|---|---|
| Phase 0 | `sessionquant/`, `pennyquant/__main__.py`, `pyproject.toml`, `README.md`, `Dockerfile`, `docs/MIGRATION.md` | 패키지 설치·새 명령·기존 기록 보존·호환 재생 |
| Phase 1 | `sessionquant/market/`, 시장 테스트 | 시점별 구성 종목, 완성된 5/15분봉, SPY·QQQ 상태, 네 전략, 미확인 거래 조건 차단 |
| Phase 2 | `sessionquant/portfolio/`, 포트폴리오 테스트 | Decimal 주문·체결, 비중·예약금·위험 예산, 추가매수 1회, 조기 폐장·청산·잔량·복구 |
| Phase 3 | `sessionquant/macro/`, `sessionquant/news/`, RSS 및 뉴스 테스트 | 공식/보조 출처 구분, GDELT 미확인 처리, 부정문·루머·캐시, LLM 예산·비용 기록 |
| Phase 4 | `sessionquant/database/`, 통합 실행·새 대시보드, DB·통합 테스트 | MySQL 원자성·멱등성·실행 임대, 저장소 이전, 재시작 복구, DB 장애 처리, 화면 표시 |

## 자동 검증 명령

```bash
python -m pytest -q
python -m ruff check sessionquant tests
python -m sessionquant doctor
python -m sessionquant demo --out data/session-validation
```

MySQL 통합 테스트는 임시 테스트용 MySQL 8 데이터베이스에서 수행합니다. 사용자 운영 DB에서 테스트 초기화·정리 코드를 실행하지 않습니다. 비밀번호·계좌 키·토큰은 테스트 출력이나 저장소에 기록하지 않습니다.

## 화면 검증

`tests/test_session_dashboard.py`는 다음을 확인합니다.

- 빈 저장소에서 가상의 계좌 평가금액이나 시장 상태를 표시하지 않음.
- Decimal 소수점 수량·평가 비중·수수료를 표시함.
- MySQL 사용 시 로컬 `.db` 파일이 없어도 DB 조회를 시도함.
- DB 오류 원문에 포함될 수 있는 비밀번호·주소를 화면에 노출하지 않음.
- 각 원장의 최근 기록 수를 제한하고 읽기 후 연결을 종료함.

## 운영 전 확인이 남는 항목

- 사용자의 로컬 MySQL 접속과 Windows·PyCharm 환경.
- 토스 계정의 실제 데이터 권한, 소수점 매매 가능 상태·최소 금액·주문 마감.
- OpenAI 모델 후보의 계정 접근 권한, 구조화 출력 지원, 실제 단가.
- 실제 뉴스 수집 지연과 S&P 500 편입 이력의 공급 범위.
- 실제 주문·체결·계좌 대사 및 GCP 운영. 이는 Phase 5~6의 범위임.

합성 데모의 통과를 실거래 성공이나 수익성 검증으로 기록하지 않습니다. 미확인 입력으로 진입을 허용하는 방식으로 테스트를 통과시키지 않습니다.

## 2026-11-14 통합 검증 기록

- Python 3.12 새 가상환경에 잠금 의존성과 SessionQuant 2.0.0 설치 완료. `sessionquant`, `python -m sessionquant`, 기존 `python -m pennyquant` 점검 통과.
- 전체 자동 테스트 530개 통과, 실제 MySQL 선택 테스트 6개는 기본 실행에서 제외. 별도 MySQL 8.0.46 실행에서 6개 모두 통과.
- 실제 MySQL에 새 SessionEngine의 합성 소수점 매수·매도 2체결 및 미청산 0건 확인.
- 원본을 유지한 SQLite→MySQL 이관, 논리 백업→빈 SQLite 복구 및 거래 중단 상태 복구 확인.
- 합성 입력에서 실제 pullback 전략 신호·수수료·소수점 체결·당일 전량 청산 및 보고서 생성 확인.
- Streamlit AppTest에서 운영 5개 화면과 뉴스 내부 3개 탭이 오류 없이 렌더링됨. Ruff 검사 통과.
- 사용자 PC MySQL·Windows, 실제 API 키·유료 LLM, 토스 실제 주문, 실제 전략 수익성, GCP 배포는 이번 검증에 포함하지 않음.
- 새 운영 경로의 설명과 CLI·화면은 한국어로 작성. 과거 재현을 위한 호환 모듈에는 이전 영어 주석·도움말 일부가 남아 있음.

커밋 단위: 이름 변경 → 시장/전략 → 포트폴리오/청산 → 뉴스/예산 → MySQL/통합/UI/문서. 모델·프롬프트의 실제 정확도 비교는 유료 API를 사용하는 별도 평가 절차로 제공하며, 이번 개발에서 평가 완료로 처리하지 않음.

## Phase 5 첫 소액 실주문 검증 경로

별도 `sessionquant/live/`와 `config/live.local.yaml`, `live-local` 명령을 추가했다. 기본은 읽기 전용 계좌 검사이며 정상 Paper 실행과 분리된다. 실제 실행은 매번 활성화·계좌 확인이 필요하고, 1종목·추가매수 금지·최대 주문 금액·최대 매도 시도로 제한한다. 부분 체결·취소 미확정·POST 타임아웃·DB 실패·재시작의 안전장치를 포함한다.

자동 검증: `tests/test_live_fractional.py` 27개 통과. 실제 MySQL 8과 모의 주문 API를 조합해 소수점 누적 체결의 DECIMAL 저장과 재시작 미활성화를 확인했다. 사용자 계좌 주문·Windows 장애·실제 최소 금액·실제 슬리피지와 비용은 미검증이다. 네 전략의 완전 자동 실거래 연결과 실제 계좌 장애 검증이 끝나기 전 Phase 5 전체 완료로 표시하지 않는다. 실행 절차는 [PHASE5_LOCAL.md](PHASE5_LOCAL.md)를 따른다.

## 대시보드 거래 제어와 마감 전 진입 차단

운영 엔진은 매 실행 새 실행 ID로 시작 대기한다. 화면은 계좌·실행 ID·60초 유효기간이 있는 제어 요청만 저장하고, 엔진이 시작·종목별 시장가 청산·전체 종료를 처리한다. 종료는 시작보다 우선하고 미체결 매수 취소와 실제 잔량 확인을 포함한다. 이전 실행의 버튼 요청이나 활성화 상태는 재시작 때 자동 복구하지 않으며 이미 확인한 청산 의도와 위험 관리는 유지한다.

공통 세션 규칙으로 청산 전 최소 30분 신규 진입 여유를 강제하고 기존 13:30 마감과 더 이른 값을 선택한다. 전송 직전과 대기 중인 모의 매수 체결에도 적용한다. 조기 폐장·늦은 체결·종료 요청과 주문 전송 사이 경합·외부 보유 수동 매도 대사를 모의 API로 검증한다. 실제 사용자 계좌에는 주문하지 않았다.
