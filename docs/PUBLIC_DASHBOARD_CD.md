# 공개 대시보드와 자동 배포

주소 하나에서 SessionQuant의 실제 시세 기반 **모의매매** 운영 화면을 봅니다. 로그인은 조회에 필요하지 않으며, 매매 시작·전체 청산·개별 매도·메모 저장에만 필요합니다.

## 접속과 권한

**공개 주소:** https://sessionquant-paper.tailf05449.ts.net:8443

| 기능 | 일반 방문자 | 관리자 로그인 후 |
| --- | --- | --- |
| 메인, 시장·종목, 전략·백테스트 | 조회·검색 | 동일 |
| 매매 내역, 뉴스·LLM, 시스템·설정 | 조회·검색·내보내기 | 동일 |
| 평가 보고서 업로드 | 브라우저 세션에서 읽기만 | 동일 |
| 매매 시작·전체 청산·개별 매도 | 조작 불가 | 실행 중인 엔진과 운영 조건을 확인한 뒤 요청 |
| 비용·충전 메모 저장 | 조작 불가 | 운영 모드에서 저장 |

휴대폰·PC 모두 Tailscale 설치 없이 공개 주소로 접속합니다. 왼쪽 메뉴의 **관리자 로그인**에 기존 비밀번호를 입력하면 같은 화면에서 조작할 수 있습니다. VM은 켜져 있어야 하지만 PC·PuTTY는 꺼도 됩니다. 기존 Tailscale 주소(443)는 같은 화면의 사설 접속 경로로 남습니다.

- 일반 방문자에게도 모든 메뉴를 표시합니다. 매매 버튼 비활성화와 별개로 서버의 명령 저장 직전에 로그인 권한을 다시 확인합니다. 청산 확인과 엔진 상태·장 운영 시간 검사는 유지합니다.
- 로그인은 서명된 서버 세션으로 관리합니다. 비밀번호는 scrypt 해시로 저장합니다. 로그인 1시간 후, 로그아웃·프로세스 재시작·비밀번호 변경 시 권한이 만료됩니다. 전체 프로세스에서 1분에 최대 5번 로그인 검사를 허용합니다.
- 통합 화면은 기존 앱의 DB 연결을 사용합니다. 이전의 별도 SELECT 전용 공개 컨테이너와 달리 **쓰기 권한 경계는 서버의 인증 검사**입니다. API 키·관리자 비밀번호를 브라우저에 전달하지 않습니다.
- 익명 방문자의 페이지별 기본 조회와 차트 조회는 5초 공유 캐시를 사용합니다. 표 필터는 방문자별 사본에 적용합니다. 관리자 제어 판단은 캐시를 사용하지 않고 현재 엔진·장부를 다시 확인합니다. LLM 상세 등 추가 조회는 기존 조회 한도를 유지합니다.
- 점검 모드에서는 로그인한 관리자도 매매를 시작하거나 메모를 저장할 수 없습니다. 매매 엔진은 운영일의 기존 시작 절차로 켜야 합니다. 점검 모드의 화면은 마지막 저장 시점 기록입니다.

## 기존 공개 화면을 통합 화면으로 전환

먼저 통합 화면 변경이 포함된 버전을 배포합니다. CD를 켰다면 main 회귀검사와 자동 배포 완료를 확인합니다. **코드 배포만으로 기존 공개 경로를 바꾸지는 않습니다.** 기존 매매·백업·정리가 끝나고 점검 화면이 실행 중인 상태에서 다음 한 번의 전환을 진행합니다.

Windows CMD에서 VM 접속:

```cmd
gcloud compute ssh sessionquant-paper --project=sessionquant --zone=us-central1-a --tunnel-through-iap
```

PuTTY에서:

```bash
sudo bash /opt/sessionquant/deploy/gcp/public_shared_enable.sh
```

기존 비밀번호를 그대로 사용하며 백업 생성·DB 삭제·비밀번호 교체는 하지 않습니다. 실행 중인 이미지의 인증 지원과 비밀번호 설정을 확인한 뒤 앱을 점검 모드로 다시 켜고, 공개 8443을 앱의 8501에 연결합니다. 성공 후 이전 공개 뷰어 컨테이너만 제거합니다. 이후 업데이트는 `/etc/sessionquant/public-shared` 표시를 확인해 통합 구성을 유지합니다.

전환이 중간에 실패하면 오류를 확인한 뒤 같은 명령으로 재시도할 수 있습니다. 인증 확인에 실패한 상태로 공개 포트를 수동 변경하지 마세요.

처음 공개하는 VM은 `sudo bash /opt/sessionquant/deploy/gcp/public_enable.sh`로 관리자 비밀번호와 기존 공개 구성을 설정한 다음 위 전환 명령을 실행합니다. 이미 전환한 VM에서 최초 설정 명령은 재실행을 차단합니다.

확인할 항목:

1. Tailscale을 끈 기기에서 공개 주소에 접속해 모든 메뉴가 보이는지 확인합니다.
2. 로그인 전 매매 시작·전체 매도 버튼이 비활성화되고 비용 메모 저장이 없는지 확인합니다.
3. 같은 주소에서 관리자 로그인·로그아웃을 확인합니다. 휴장·점검 모드에서는 로그인해도 매매가 시작되지 않습니다.

Funnel이 HTTPS 연결을 제공하므로 별도 도메인이나 GCP의 8501·8502 포트 개방은 필요하지 않습니다. Funnel 정책 승인과 대역폭 제한은 적용됩니다.

## CD 활성화

```bash
sudo bash /opt/sessionquant/deploy/gcp/cd_enable.sh
```

GitHub Actions의 SSH 비밀키나 장기 GCP 키를 추가하지 않습니다. VM이 5분마다 공개 저장소를 확인하는 **pull 방식 CD**입니다.

1. `main`의 정확한 커밋에 대해 `.github/workflows/ci.yml`의 최신 push 검사가 성공했는지 확인합니다. PR 검사만 통과한 커밋, 실패·진행 중인 재검사는 배포하지 않습니다.
2. 휴장·정규장 마감 후이며 매매 프로그램이 실행 중이지 않아야 합니다. OFFLINE 상태, 보유·미체결·청산 요청 없음, 백업·정리 작업 없음도 확인합니다. 조건이 맞지 않으면 `DEFERRED`로 기다립니다. 장전에도 자동 배포는 기다립니다.
3. 기존 업데이트 스크립트의 잠금·검증·백업·자료 정리 절차를 그대로 실행합니다. 매매 시작이나 무조건 백업 생략은 하지 않습니다.
4. 성공 후 **점검 화면만** 켭니다. 통합 구성은 인증 설정·공개 경로·HTTP 응답을 확인하고, 아직 전환하지 않은 기존 구성은 공개 뷰어도 갱신합니다.
5. 실패·프로세스 강제 종료 시 시도 표시를 남기고 다음 자동 시도를 차단합니다. 새 커밋이 올라와도 백업을 반복 생성하지 않습니다. DB 변경 가능성이 있으므로 자동 코드 되돌리기는 하지 않습니다.

실행 중 작업이 오래 걸려도 다음 타이머가 중복 실행하지 않습니다. 업데이트 서비스의 전체 시간 한도는 3시간입니다. 통합 화면은 앱과 함께 재시작되므로 배포 중 잠시 연결이 끊길 수 있습니다. 야간 정리 중에는 같은 주소에 자료 정리 진행 화면이 표시되며, 정리가 끝나면 점검 대시보드로 돌아옵니다.

확인:

```bash
sudo cat /var/lib/sessionquant/cd/status.json
sudo systemctl list-timers sessionquant-cd.timer --no-pager
sudo journalctl -u sessionquant-cd.service -n 30 --no-pager
sudo tail -n 40 /var/lib/sessionquant/cd/deploy.log
```

`CURRENT`: 최신 코드 / `DEFERRED`: 안전 조건 대기 / `COMPLETE`: 배포 완료 / `FAILED`·`BLOCKED`: 수동 확인 필요. 첫 검사 전에는 상태 파일이 없을 수 있습니다. 서비스 로그와 배포 로그는 관리자 전용입니다.

### 이전 배포가 바꾼 스크립트 실행 권한

이전 업데이트는 `deploy/gcp/*.sh`에 일괄 실행 권한을 추가했습니다. Git에서 실행 파일이 아닌 것으로 기록된 스크립트가 다음 버전에서 수정되면, 내용이 그대로여도 배포 준비 검사가 이를 알 수 없는 로컬 수정으로 거부할 수 있었습니다. 이 경우 앱 중지·백업 전에 중단됩니다.

수정된 업데이트는 파일 내용이 현재 HEAD와 같고, `deploy/gcp`의 `.sh` 파일이 `100644 → 755`로 바뀐 경우만 확인해 백업 후 반영합니다. 임의 내용 변경·스테이징·심볼릭 링크는 계속 거부합니다. 새 업데이트는 Git의 실행 권한을 그대로 보존합니다. 실패 표시를 무조건 지우거나 `git reset --hard`로 우회하지 말고, 로그와 차이를 확인한 뒤 수정본으로 재시도하세요.

실패 후 로그를 검토하고 기존 복구 절차로 운영 상태를 확인한 다음에만 재시도 차단을 해제합니다:

```bash
sudo systemctl stop sessionquant-cd.timer
# 실행 중 배포가 없는지 확인. 실행 중 서비스를 강제로 끊지 않습니다.
sudo systemctl status sessionquant-cd.service --no-pager
# 원인 해결·복구 확인 후에만 실행:
sudo rm /var/lib/sessionquant/cd/attempt.json
sudo systemctl start sessionquant-cd.timer
```

자동 배포 중지: `sudo systemctl disable --now sessionquant-cd.timer` (실행 중 배포는 끝까지 진행).

공개 접속만 중지:

```bash
sudo tailscale funnel --https=8443 off
sudo rm -f /etc/sessionquant/public-enabled /etc/sessionquant/public-shared
sudo docker compose -f /opt/sessionquant/deploy/gcp/compose.public.yaml down
```

관리자 Tailscale 접속·DB·매매 기록은 삭제하지 않습니다.
