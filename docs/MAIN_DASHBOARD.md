# 메인 화면의 실제 계좌·OpenAI 비용

기존 다섯 탭을 유지한다. 상단의 토스 실제 계좌와 전략 장부는 분리하며, 원화·달러도 각각 표시한다. 실제 계좌 주식 평가금액과 매수 가능 금액을 총자산·누적 입금액으로 간주하지 않는다. 누락 응답은 `—`, 갱신 실패·60초 이상 지연은 경고로 표시한다.

## 실행

저장한 `.env`의 토스·MySQL 접속 정보를 사용한다. 이전 토스 수집 프로그램은 먼저 `Ctrl+C`로 종료한다.

```powershell
# 메인 화면: 시세·뉴스·Paper 전략 + 실제 계좌 조회
.\venv\Scripts\python.exe -m sessionquant run --config config/sessionquant.yaml
# http://localhost:8501

# 또는 실제 계좌만 조회, 동일한 메인 화면 형식
.\venv\Scripts\python.exe -m sessionquant run-account
# http://localhost:8502
```

`run`의 실제 계좌 조회는 시세 수집기와 같은 인증 클라이언트를 재사용한다. 조회 결과가 Paper의 자본·체결·포지션을 덮어쓰지 않는다. Paper의 신규 매수는 기존 **매매 시작** 버튼을 누른 뒤 허용한다. `run-account`에는 거래 엔진·뉴스 분석이 없다. 표시 형식은 같지만 시세·전략 탭이 비어 있을 수 있다.

기존 `live-local --dashboard`도 메인 화면을 사용한다. 실제 주문 활성화 규칙, 종목별 매도 확인, 당일 청산과 제한시간은 유지한다. 현재 이 경로는 Phase 5의 1종목 소액 검증이며 네 전략·뉴스의 완전 자동 실거래 통합은 별도 작업이다.

## OpenAI 사용량·충전 기록

세 항목을 표시한다.

| 항목 | 기준 |
|---|---|
| 프로그램 누적 비용 | 선택한 운영 DB의 월별 영속 비용 원장 합계 |
| 이번 달 프로그램 비용 | UTC 기준 이번 달 원장 |
| OpenAI 충전 누계 · 직접 기록 | 사용자가 입력한 누적 충전 금액 |

**OpenAI 충전 누계 기록**을 펼쳐 달러 누적 금액을 적고 저장한다. 실제 결제 요청을 전송하지 않는다. 입력한 값은 DB에 보관되어 재실행 후에도 유지된다. 이 값에서 프로그램 추정 비용을 뺀 수치를 공식 잔액으로 표시하지 않는다.

일반 API 키에 대해 공식 선불 충전 내역·현재 잔액을 자동 조회하는 것으로 구현하지 않았다. [공식 사용량](https://platform.openai.com/usage)과 [청구·잔액](https://platform.openai.com/settings/organization/billing/overview)을 직접 확인한다. 조직 Costs API는 관리자 키가 필요한 별도 청구 조회이며 충전 잔액 API와 같지 않다.

토큰 비용은 설정 단가로 계산한 추정치다. 응답이 불명확하면 기존 보수적 예약 비용이 반영될 수 있다. 미결 예약은 확정 비용과 구분하여 원장에 유지한다. 다른 앱의 비용·이전 엔진의 미수집 이력·다른 DB는 합산하지 않는다. 비용 원장 자체가 없으면 `—`로 표시하며 0으로 확정하지 않는다.

일반 `run`은 해당 Paper 실행 DB를 읽는다. `run-account`와 `live-local`의 화면은 `config/sessionquant.yaml`에 지정한 Paper DB의 비용·충전 기록을 읽는다. MySQL의 LIVE_LOCAL 계좌 기록과 PAPER_LOCAL 비용 원장을 분리한다. 대시보드 프로세스에 토스·OpenAI 키를 전달하지 않고 DB에서 표시 자료를 읽는다.

## LLM을 사용할 수 없을 때

OpenAI 키 미설정·잔액/할당량 부족·인증 오류·요청 제한·일시 장애를 구분한다. 연결 경고는 메인 비용 패널·운영 경고와 엔진 로그에 표시한다. 부족 여부는 실제 생성 요청의 오류 코드로 판단한다. `insufficient_quota`는 잔액 외 사용 한도 설정도 확인해야 한다.

- 충전 누계 미입력이나 $0 메모는 매매·분석을 차단하지 않는다.
- 잔액 부족 응답 후 10분, 일반 요청 제한·일시 장애 후 60초 동안 반복 요청을 억제한다. 충전 후 다음 분석이 필요할 때 재시도한다.
- 미분석 뉴스는 UNKNOWN으로 남기고 차트 조건·시장 상태·자금·위험 규칙으로 매매를 판단한다. 거래 신호가 없으면 매수하지 않는다.
- 손절·수동 매도·당일 청산은 뉴스 작업과 별도로 계속한다.
- 기존 확인된 기업 악재나 공식 경제 일정의 신규 진입 제한은 그대로 유지한다.

## 한 번에 연결 점검

```powershell
.\venv\Scripts\python.exe -m sessionquant check-connections
# 연결 없이 설정 유무만 검사
.\venv\Scripts\python.exe -m sessionquant check-connections --offline
```

토스 시세·계좌, DB 접속, OpenAI 모델 메타데이터, Alpaca·SEC·설정된 기업 RSS·공식 기관 RSS·Treasury·GDELT·FRED를 검사한다. 실제 주문·취소·LLM 생성은 하지 않는다. OAuth 토큰 발급은 필요할 수 있다. 결과에 API 키와 DB 비밀번호를 출력하지 않는다.

`ok`는 해당 읽기 조회 성공, `partial`은 일부 항목 실패, `not_configured`·`missing_credentials`는 설정 누락, `error`는 연결 실패다. 모델별 `accessible`은 모델 메타데이터 접근 여부로서 JSON 생성·잔액을 검증하지 않는다. 실제 주문 권한도 읽기 조회만으로 검증하지 않는다.

실행 중인 엔진을 발견하면 `skipped_active_collector`로 토스 검사만 건너뛴다. DB가 끊겨 엔진 실행 여부를 확인하지 못하면 `skipped_database_unavailable`로 건너뛴다. 토스 토큰 재발급이 기존 수집 인증을 끊을 수 있어 **모든 수집기를 종료한 뒤 검사**한다. 종료 직후 60초까지는 마지막 상태가 남을 수 있다. 다른 DB·다른 PC의 실행 여부를 자동으로 모두 탐지하는 기능은 아니다.

## 개발 환경 검증

2026-11-14 기준 MySQL 8 격리 환경을 포함한 전체 자동 테스트 617개, Ruff 및 변경 형식 검사가 통과했다. 잔액 부족·키 미설정 상태의 기술적 진입/당일 청산, 확인된 악재 유지, 계좌 조회 장애 격리, 실제 계좌 메인 표시, 운영 환경별 비용 분리를 검증했다. 토스·OpenAI 응답은 모의 HTTP로 검사했으며 사용자 실계좌 주문이나 유료 LLM 생성을 실행하지 않았다. 사용자 PC의 실제 키·MySQL 연결은 위 점검 명령으로 확인한다.
