# 대시보드 화면과 표시 기준

어떤 화면에서 무엇을 확인하는지 설명하는 참고 문서입니다. 이 문서는 현재 소스의 모의매매 홈을 기준으로 합니다. 서버에 예전 이미지가 실행 중이면 업데이트 전 화면이 보일 수 있습니다.

[문서 목록](../README.md) · [매매 흐름](../TRADING_PROCESS.md) · [용어 설명](../GLOSSARY.md)

## 메인에서 보는 것

홈은 **현재 상태 → 시장 흐름 → 집중 감시 → 보유 종목·매매 기록 → AI 설명** 순서입니다. 긴 수치표는 상세 메뉴에서 확인합니다.

| 위치 | 보여주는 내용 | 해석할 때 구분할 것 |
| --- | --- | --- |
| 상단 매매 제어 | 시작·중지 등 사용자의 요청과 엔진 상태 | 자동매매가 켜져도 조건이 맞아야 주문함 |
| 상태·자산 요약 | 시세, 종목, 모의 총자산, 매수 가능 금액, 일간·총 수익률 | 저장 장부·최근 수신 상태이며 실계좌 잔액이 아님 |
| 시장 흐름 카드 | SPY·QQQ·SOXX 가격·등락률·당일 차트 | 지수 자체가 아니라 시장 참고용 ETF |
| 집중 감시 카드 | 최대 10종목의 티커·한글 이름, 가격·전일 대비 %, 상승 → 조정 → 반등 단계 | 반등 확인과 주문 승인·체결은 각각 다른 단계 |
| 보유 종목 | 모의 평가액·평가 손익 금액과 %, 최근 매수·매도 체결 | 새 시세 수신 전에는 이전 평가가 남을 수 있음 |
| 매매 기록 | 15개씩 최대 5페이지의 모의 체결과 주문에 연결된 사유 | 체결된 기록만 표시하며 과거 사유를 임의로 만들지 않음 |
| AI 설명 | 저장된 전략 판단에 대한 설명과 작성 상태 | 설명이 매수 허가나 체결 증거가 아님 |
| 뉴스·AI 수집 현황 펼치기 | 최근 24시간 기사·분석 건수 | 저장 기록이며 현재 연결 성공·분류 정답률과 다름 |

가격은 수신한 관측가 또는 호가 중간값을 출처·시각과 함께 표시합니다. 오래된 값은 ‘이전 가격’으로 구분합니다. 목록·전략 평가가 오래되면 ‘목록 갱신 대기’·‘판단 대기’로 표시하며, 새 화면 갱신만으로 과거 결과를 현재 결과로 바꾸지 않습니다. 정규장 전에는 ‘개장 대기’가 정상일 수 있습니다.

장전에도 SPY·QQQ·SOXX의 수신 가격을 표시합니다. 가격을 못 받으면 **장전 시세 대기**, 가격이 오래되면 **가격 갱신 대기**, 연결이 끊기면 **재접속 중**으로 구분합니다. 정규장 전용 ETF 차트와 당일 1·5·15분봉 상태에는 **개장 대기와 한국시간 개장 시각**을 표시합니다. 정규장 전용 AI 브리핑도 **개장 대기**로 표시하며, 이전의 한도 제한은 ‘이전 분석 시도’와 그 시각으로 따로 보여 줍니다. 이전에 성공한 설명은 원래 분석 시각과 함께 유지합니다. 이 안내를 위해 AI를 추가 호출하거나 호출 횟수를 소모하지 않습니다.

## 자세한 내용 찾기

시장 흐름의 **가격은 수신할 때 갱신하고 차트는 1분마다 한 점을 남깁니다.** 정규장 개장부터 수신한 구간을 보존하며, 수집하지 못한 시간은 채우지 않습니다. 전일 종가보다 높으면 빨강, 낮으면 파랑이고, 세로축은 수신 가격 범위에 맞춥니다. 전일 종가가 표시 범위 밖이면 그 방향을 글로 안내합니다.

폐장·휴장일에는 마지막 거래일의 저장된 차트와 집중 목록을 보여 줍니다. 저장 목록이 없으면 없다고 안내하고, 확인된 종가가 없으면 마지막 장중 가격을 종가로 바꾸어 표시하지 않습니다. 이전 버전이 최근 한 시간만 저장했다면 새 버전 설치만으로 앞 시간대가 복원되지는 않습니다.

| 메뉴 | 확인할 내용 |
| --- | --- |
| 시장·종목 → 시세·품질 | 최신 호가, 분봉 연속성, 프로필에 필요한 입력 상태 |
| 시장·종목 → 감시·집중 종목 | 후보와 집중 목록, 제외·대기 이유 |
| 시장·종목 → 매수 판단 | 전략 조건·뉴스 가점·주문 제한. **전략 → AI → 주문 상세 기록**에서 근거 확인 |
| 시장·종목 → 거래량 비교 / 시장 참고 | RVOL·ETF 등 별도 참고. 단순 전략의 필수 입력 여부와 구분 |
| 시장·종목 → 처리 속도 / 분석 이력 | 지연 구간·과거 판단 기록. 분봉 지연 진단은 [웹소켓 운영 안내](../WEBSOCKET_ROLLOUT.md) 참고 |
| 전략·백테스트 | 저장한 전략·재생·실험 자료 |
| 매매 내역 | 주문 상태·실제 모의 체결·수량·손익 |
| 뉴스·LLM | 기사 원문 근거, 분석 요청·응답, 비용·예산 |
| 시스템·설정 | 연결·설정·운영 기록 |

단순 전략에서는 뉴스가 후보 순위에 가점을 주고 AI가 판단을 설명합니다. 이전 프로필의 악재·경제 일정 차단 규칙을 현재 단순 전략의 주문 조건으로 해석하지 않습니다. 각 설정의 차이는 [개발 안내](../DEVELOPMENT.md)를 참고하세요.

## 전략·백테스트의 일별 성과

총자산은 **일별 꺾은선($)**, 일간 수익률은 **일별 막대(%)**로 표시합니다. 미국 뉴욕 날짜 기준 하루의 마지막 저장값을 사용하고, 오늘은 새 기록을 조회할 때 같은 날짜의 점이 바뀝니다. 마지막 기록 시각은 한국시간으로 표시합니다. 기록이 하루뿐이어도 점이 보이며, 없는 날짜나 기준 자산을 임의로 채우지 않습니다. 최근 최대 2,000일 기록을 조회합니다.

| 표의 항목 | 뜻 |
| --- | --- |
| 총자산 ($) | 예수금과 보유 종목 평가액을 합친 모의 장부 금액 |
| 일간 수익률 (%) | `(총자산 ÷ 하루 시작 자산 − 1) × 100`. 평가손익과 이미 낸 수수료 포함 |
| 누적 실현손익 ($) | 이 모의 장부에서 매도로 확정된 손익의 합계. 매일 초기화되는 하루 손익이 아님 |
| 하루 시작 자산 ($) | 미국 날짜가 바뀐 뒤 장부를 처음 갱신할 때 저장한 기준 자산. 이전의 ‘추가 정보 2’ |
| 신규 매수 중지 | 손실 한도에 따라 신규 매수가 중지됐는지 여부. 이전의 ‘추가 정보’ |

금액에는 `$`, 수익률에는 `%`를 붙여 화면과 CSV에 표시합니다. 표시값은 소수점 둘째 자리까지 버리고, 원본 장부와 계산값은 정밀도를 유지합니다. 기준 자료가 없는 수익률은 `—`입니다. 시간별 계좌 기록 대신 일별 기록을 읽으므로 최근 몇 분의 자료만 전체 성과처럼 보이는 문제를 줄입니다.

## 화면 갱신과 엔진 실행

자동 갱신을 켜면 홈의 시세·종목·장부는 5초, 홈의 뉴스·AI 영역은 60초마다 저장 기록을 다시 읽습니다. 시장·종목의 선택한 화면은 10초, 뉴스·LLM은 30초 주기입니다. **처리 속도·분석 이력과 다른 메뉴는 수동 새로고침**입니다. 선택하지 않은 상세 표는 매번 조회하지 않습니다.

자동 갱신을 끄거나 브라우저를 닫아도 서버 엔진은 계속 실행됩니다. Cloud Shell의 SSH 터널을 `Ctrl+C`로 끊는 것도 서버 프로그램 종료와 다릅니다. 반대로 화면이 열려 있어도 엔진의 최근 실행 신호가 없으면 현재 수집 중이라고 단정하지 않습니다.

버튼은 최신 제어 상태를 확인해 DB에 요청을 남기고 엔진이 처리합니다. 화면 갱신 주기는 주문 처리 시간을 보장하지 않습니다. URL의 메뉴·하위 화면 선택값을 통해 다시 접속할 때 선택을 복원합니다. 원본 기록 표시를 켜면 조회량이 늘어날 수 있습니다.

## 실행과 실제 계좌의 구분

현재 추천 프로필을 명시해 실행합니다. 가상환경이 활성화된 터미널 기준입니다.

```powershell
python -m sessionquant run --config config/sessionquant.strategy-lab-websocket.example.yaml
# http://127.0.0.1:8501
```

이 예시는 실제 계좌 조회가 꺼져 있고 가상 자금으로만 거래합니다. 화면의 매매 시작을 누르기 전에도 시세·뉴스 수집과 설정된 유료 분석은 실행될 수 있습니다. `--config`를 생략하면 다른 기본 설정을 읽으므로 생략하지 않습니다.

실제 계좌만 확인하는 별도 명령은 `python -m sessionquant run-account`이며 기본 포트는 8502입니다. 거래 엔진·뉴스 분석이 없는 계좌 화면으로, 모의매매 홈과 목적이 다릅니다. 원화·달러와 실제 주식 평가금액·매수 가능 금액을 구분하며 실제 계좌 조회가 모의 자본을 덮어쓰지는 않습니다. 별도 `live-local` 기능은 [실주문 검증 참고](PHASE5_LOCAL.md)에 설명합니다.

## OpenAI 비용·월 한도·충전 메모

비용·예산·충전 메모는 **뉴스·LLM → LLM 사용량**에서 확인한다. 월 한도와 충전액은 서로 다른 값이다. 예를 들어 $10 충전 메모를 저장해도 월 한도 $3 설정은 그대로다. [07 운영 안내](https://github.com/taegyoo1104/pennyquant/blob/03fc270546c72c15c7ffed9af9b60a7207f3ae14/docs/archive/stages/STAGE07_LLM.md)에 호출 감사와 보관 정책을 설명한다.

| 항목 | 기준 |
|---|---|
| 프로그램 누적 비용 | 선택한 운영 DB의 월별 영속 비용 원장 합계 |
| 이번 달 프로그램 비용 | UTC 기준 이번 달 원장 |
| OpenAI 충전 누계 · 직접 기록 | 사용자가 입력한 누적 충전 금액 |
| 수동 확인 기반 추정 잔액 | 마지막 확인 잔액·확인 시각 이후 자체 비용·미결 예약을 차감한 추정 |
| 공식 조직 비용 | 별도 공식 집계 수집기는 미연결, 기본 UNKNOWN |

LLM 상세의 **수동 잔액·충전 메모**를 펼쳐 달러 누적 금액이나 수동 확인 잔액·시각을 적고 저장한다. 실제 결제 요청을 전송하지 않는다. 입력한 값은 DB에 보관되어 재실행 후에도 유지된다. 충전 누계를 잔액으로 바꾸지 않으며 추정 잔액은 공식 잔액과 구분한다. 확인 시각을 걸친 요청이나 시각 미확인 과거 기록은 UNKNOWN으로 표시한다.

일반 API 키에 대해 공식 선불 충전 내역·현재 잔액을 자동 조회하는 것으로 구현하지 않았다. [공식 사용량](https://platform.openai.com/usage)과 [청구·잔액](https://platform.openai.com/settings/organization/billing/overview)을 직접 확인한다. 조직 Costs API는 관리자 키가 필요한 별도 청구 조회이며 충전 잔액 API와 같지 않다.

토큰 비용은 설정 단가로 계산한 추정치다. 제공자 보고 토큰을 사용해도 공식 청구액은 아니다. usage 없는 오류·timeout은 보수적 예약액에 기반한 미확정 추정이며 실제 비용 0으로 표시하지 않는다. 정산 실패의 미결 예약은 정산된 추정 비용과 구분하여 원장에 유지한다. 다른 앱의 비용·이전 엔진의 미수집 이력·다른 DB는 합산하지 않는다. 비용 원장 자체가 없으면 `—`로 표시하며 0으로 확정하지 않는다.

일반 `run`은 해당 Paper 실행 DB를 읽는다. `run-account`와 `live-local`의 화면은 `config/sessionquant.yaml`에 지정한 Paper DB의 비용·충전 기록을 읽는다. MySQL의 LIVE_LOCAL 계좌 기록과 PAPER_LOCAL 비용 원장을 분리한다. 대시보드 프로세스에 토스·OpenAI 키를 전달하지 않고 DB에서 표시 자료를 읽는다.

## LLM을 사용할 수 없을 때

키 미설정·잔액/한도 부족·인증 오류·요청 제한은 뉴스·LLM과 운영 기록에서 구분합니다. 충전 메모 미입력 자체는 차단 사유가 아닙니다. `insufficient_quota` 응답은 실제 잔액뿐 아니라 제공자 한도도 확인해야 합니다.

잔액 부족 응답 후 10분, 일반 요청 제한·일시 장애 후 60초 동안 반복 요청을 억제합니다. 다음 분석 시 재시도하며, 미분석 기사를 정상 분석으로 표시하지 않습니다. 단순 전략의 가격 조건과 손절·청산은 별도로 판단합니다. 예전 엄격 프로필에서는 이미 확인한 뉴스·일정 제한도 계속 적용될 수 있습니다.

## 주문·생성 없이 연결 점검

```powershell
python -m sessionquant check-connections --config config/sessionquant.strategy-lab-websocket.example.yaml --offline
python -m sessionquant check-connections --config config/sessionquant.strategy-lab-websocket.example.yaml
```

첫 명령은 설정 유무만, 둘째는 토스·DB·뉴스·모델 메타데이터의 읽기 연결을 검사합니다. 주문·취소·LLM 생성은 하지 않습니다. `ok`는 해당 조회 성공이며 모델 JSON 응답·분류 정확도·공식 선불 잔액·실제 주문 권한을 검증했다는 뜻은 아닙니다.

토스 인증은 새 토큰 발급이 기존 수집기와 충돌할 수 있습니다. 실행 중인 엔진을 발견하면 `skipped_active_collector`, DB 때문에 실행 여부를 확인하지 못하면 `skipped_database_unavailable`로 토스 검사를 건너뜁니다. 토스까지 검사하려면 기존 수집기를 정상 종료한 뒤 실행합니다. 다른 DB·PC의 엔진까지 자동으로 찾는 기능은 아닙니다.

화면 코드는 [operations_overview.py](../../sessionquant/dashboard/operations_overview.py), 집중 카드 기준은 [home_cards.py](../../sessionquant/dashboard/home_cards.py)에 있습니다. 과거 테스트 수와 당시 화면 결과는 [단계별 보관 기록](https://github.com/taegyoo1104/pennyquant/blob/03fc270546c72c15c7ffed9af9b60a7207f3ae14/docs/archive/stages/STAGE08A_DASHBOARD.md)에서 확인하며 현재 환경의 검증 완료로 취급하지 않습니다.
